# Kustomize

Kustomize is a standalone tool, and subcommand of `kubectl` to help manage
building manifest.

Use YAML merging to generate YAML manifest for deployment.

All the deets come from [Declarative Management of Kubernetes Objects Using
Kustomize]. So if you need a better explanation look there.

If you'd like to see what a `kustomization.yaml` will build without deploying
anything to the cluster, then run:

```shell
kubectl kustomize <kustomization_directory>
```

NOTE: You can run this as you build each piece to stay on track. Also, the
directory MUST contain a `kustomization.yaml`.

When you're finally done building and you verified that your Kustomize looks
as it should, then you can deploy it with the command:

```shell
kubectl apply -k <kustomization_directory>
```

## Configuration File

These are fields that you can add to your `kustomization.yaml`.

To add the same namespace to all resources.

```yaml
namespace: <value>
```

To add more resources list a manifest file in the `resources` list.

```yaml
resources:
- deployment.yaml
```

When you only want to update parts of a base manifest, you can you `patches`
and change the parts you require. Make a new manifest with ONLY the diresired
fields changed. For example, you change just the replicas of a base
deployment.yaml to `3` like so.

```yaml
# ./kustom-deployment/base/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
spec:
  replicas: 3
```

```yaml
# ./kustom-deployment/overlays/production/kustomization.yaml
resources:
  - ../../base
patches:
- deployment.yaml
```

NOTE: It is unfortunate that you MUST also include the `apiVersion`, `kind`, and
`metadata.name`. But that is required to match which resource to update.
Otherwise, this could be no different from Helm charts.
