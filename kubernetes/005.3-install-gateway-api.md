# Gateway API

This is something that SHOULD be done by a **Cluster Admin** or
**Cluster Provider**.

We install the Gateway API CRDs and then the Nginx Gateway Fabric as our Gateway
API Controller.

## Install Standard Channel

1. Verify they are NOT installed already:
   ```shell
   kubectl get crd grpcroutes.gateway.networking.k8s.io
   kubectl get crd refer
   ```
   If they return "not found" in the output, then proceed. Otherwise, if you’ve
   previously installed a version of a channel, refer to the [v1.2 upgrade
   notes].
2. Install
   ```shell
   GAPI_VER=v1.5.1
   wget -O gateway-api-standard-${GAPI_VER}.yaml https://github.com/kubernetes-sigs/gateway-api/releases/download/${GAPI_VER}/standard-install.yaml
   kubectl apply --server-side -f gateway-api-standard-${GAPI_VER}.yaml
   ```
3. Pick a Gateway API Controller to install:

   ```shell
   kubectl kustomize "https://github.com/nginx/nginx-gateway-fabric/config/crd/gateway-api/standard?ref=v2.6.3" | kubectl apply -f -
   kubectl create namespace nginx-gateway

   kubectl apply -f - <<EOF
   apiVersion: cert-manager.io/v1
   kind: Issuer
   metadata:
     name: selfsigned-issuer
     namespace: nginx-gateway
   spec:
     selfSigned: {}
   ---
   apiVersion: cert-manager.io/v1
   kind: Certificate
   metadata:
     name: nginx-gateway-ca
     namespace: nginx-gateway
   spec:
     isCA: true
     commonName: nginx-gateway
     secretName: nginx-gateway-ca
     privateKey:
       algorithm: RSA
       size: 2048
     issuerRef:
       name: selfsigned-issuer
       kind: Issuer
       group: cert-manager.io
   ---
   apiVersion: cert-manager.io/v1
   kind: Issuer
   metadata:
     name: nginx-gateway-issuer
     namespace: nginx-gateway
   spec:
     ca:
       secretName: nginx-gateway-ca
   EOF

   kubectl apply -f - <<EOF
   apiVersion: cert-manager.io/v1
   kind: Certificate
   metadata:
     name: nginx-gateway
     namespace: nginx-gateway
   spec:
     secretName: server-tls
     usages:
     - digital signature
     - key encipherment
     dnsNames:
     - ngf-nginx-gateway-fabric.nginx-gateway.svc
     issuerRef:
       name: nginx-gateway-issuer
   EOF

   kubectl apply -f - <<EOF
   apiVersion: cert-manager.io/v1
   kind: Certificate
   metadata:
     name: nginx
     namespace: nginx-gateway
   spec:
     secretName: agent-tls
     usages:
     - "digital signature"
     - "key encipherment"
     dnsNames:
     - "*.cluster.local"
     issuerRef:
       name: nginx-gateway-issuer
   EOF

   kubectl apply --server-side -f https://raw.githubusercontent.com/nginx/nginx-gateway-fabric/v2.6.3/deploy/crds.yaml

   kubectl apply -f https://raw.githubusercontent.com/nginx/nginx-gateway-fabric/v2.6.3/deploy/default/deploy.yaml
   ```

   NOTE: We are trying `kgateway` because it looks like the simplest option at
   the time.

Server-Side Apply provides an optional mechanism for your cluster's control
plane to track changes to an object's fields. At the level of a specific
resource, Server-Side Apply records and tracks information about control over
the fields of that object.


NOTE: For more in-depth info on installing the Gateway API CRDs and controller,
then see [Getting started with Gateway API]. Which you should do before
deploying to a production environment your first time.


IMPORTANT!: Avoid moving backwards. New versions of CRDs can add new fields and
features. Rolling back to a previous version of these CRDs could result in a
loss of that configuration.
