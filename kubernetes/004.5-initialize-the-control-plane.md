# Initialize the Control Plane

## Prerequisites

In order to make a cluster "DualStack" you'll need:

1. Kubernetes 1.20 or later.
2. Nodes with routable IPv6 and IPv4  addresses.
3. A network plugin that supports dual-stack.
4. Pass in IPv6 and IPv4 CIDRs to the following components:
   1. `kube-apiserver` set option `--service-cluster-ip-range=<IPv6 CIDR>,<IPv4 CIDR>`
   2. `kube-controller-manager` set options
      ```
      --cluster-cidr=<IPv6 CIDR>,<IPv4 CIDR>
      --service-cluster-ip-range=<IPv6 CIDR>,<IPv4 CIDR>
      --node-cidr-mask-size-ipv4|--node-cidr-mask-size-ipv6
      ```
   3. `kube-proxy` (or replacement) set option `--cluster-cidr=<IPv6 CIDR>,<IPv4 CIDR>`
   4. `kubelet` set option `--node-ip=<IPv6 IP>,<IPv4 IP>`

NOTE: If you list IPv6 CIDRs first and set the kube-apiserver
`--advertise-address` to an IPv6 address, then the cluster will be IPv6 Primary,
so it will default to use IPv6 address and use IPv4 as backups.

For more details review [Configure IPv4/IPv6 dual-stack].

## Start Kubelet Service

Time to start the `kubelet` service on the control-plane which, in turn, it will
start the control-plane components using their manifest located in
`/etc/kubernetes/manifest` directory.

1. Make a configuration for the `kubelet`:
   1. Make a `kubelet` config and place it in `/var/lib/kubelet`, there is a
      sample in `samples/config.yaml` in this repository.

      ```shell
      sudo mkdir -p /var/lib/kubelet
      sudo cp /vagrant/config.yaml /var/lib/kubelet
      ```

      NOTE: Options `rotateCertificates` and `serverTLSBootstrap` have been
      enabled. This ensures that a new and proper `kubelet` serving certificate
      is generated, listing both hostnames and IPs its SANs. These will also
      auto-renew when their time to expire is near.
2. Make a `systemd` unit for the `kubelet.service` which tells the `kubelet`
   service where to find its configuration file and the kubeconfig for
   authenticating with the `kube-apiserver`.

   ```shell
   getIps () {
      iface=${1}
      export IPV4=$(ip -4 addr show scope global dev ${iface} | grep "inet\b" | awk '{print $2}' | cut -d/ -f1)
      export IPV6=$(ip -6 addr show scope global dev ${iface} | grep "inet6\b" | awk '{print $2}' | cut -d/ -f1)
   }
   getIps "enp0s8"
   sudo mkdir -p /etc/systemd/system/kubelet.service.d
   cat /vagrant/kubelet.service.tmpl | envsubst | sudo tee /etc/systemd/system/kubelet.service.d/kubelet.conf
   ```
3. Copy the `kubelet` key and certificate, and kubeconfig into place.

   ```shell
   sudo mkdir -p /var/lib/kubelet/pki .
   sudo cp ~/certs/control-plane-01.key /var/lib/kubelet/pki/kubelet.key
   sudo cp ~/certs/control-plane-01.crt /var/lib/kubelet/pki/kubelet.crt
   sudo cp ~/certs/control-plane-01.conf /etc/kubernetes/kubelet.conf
   ```
4. Start the cluster components.

   ```shell
   sudo systemctl daemon-reload
   sudo systemctl start kubelet.service
   ```
5. Then check the status of the `kubelet` to make sure it started successfully.

   ```shell
   sudo systemctl status kubelet.service
   ```
6. Mark the node as a control-plane by adding the following Label and Taint.
   The Taint will prevent Pods from being scheduled on the control-plane unless
   configured to do so; while the label distinguishes it from worker nodes.

   ```shell
   sudo kubectl label nodes control-plane-01 node-restriction.kubernetes.io/control-plane=true \
     --kubeconfig=/etc/kubernetes/super-admin.conf
   sudo kubectl taint nodes control-plane-01 control-plane:NoSchedule \
     --kubeconfig=/etc/kubernetes/super-admin.conf
   ```

   NOTE: We have not set a default kubeconfig for accessing the cluster at this
   point, which is why we have to specify one. Very useful when you need to try
   out a different config for any reason.

7. When the `kubelet` started the cluster it may have generated a CSR to allow
   itself to generate its own certificate. List CSRs with `kubectl get csr`,
   then approve with `kubectl certificate approve <csr-name>`.

   NOTE: This ensures that a new kubelet server certificate is generated with
   hostnames and IPs

   ```shell
   sudo openssl x509 -text -noout -in /var/lib/kubelet/pki/kubelet-server-current.pem
   ```
8. Backup the `kube-apiserver.yaml` manifest:

   ```shell
   mkdir -p backups
   sudo cp /etc/kubernetes/manifest/kube-apiserver.yaml ~/backups/kube-apiserver-$(date +%F).yaml
   ls ~/backups
   ```

NOTE: If your having issues you can review the `kubelet` logs with
`sudo journalctl -u kubelet.service`.
