# Install CNI Calico

This installs [Calico The Hard Way].

## AWS

Normally we'd use Amazon VPC CNI plugin. But were running into issues using it
in IPv6 only mode. Plus there are other issue you'd want to watch out for. So
we are going to install Calico as our Network CNI plugin instead. We will use
the options:

| Policy | IPAM   | CNI    | Overlay | Routing |
|--------|--------|--------|---------|---------|
| Calico | Calico | Calico | VXLAN   | Calico  |

For more details see [Determine best networking option: AWS].

It's also working reviewing
[Configure Kubernetes control plane to operate over IPv6].

## Get Started

1. Configure NetworkManager.

   ```shell
   cat <<TXT | sudo tee -E /etc/NetworkManager/conf.d/calico.conf
   [keyfile]
   unmanaged-devices=interface-name:cali*;interface-name:tunl*;interface-name:vxlan.calico;interface-name:vxlan-v6.calico;interface-name:wireguard.cali;interface-name:wg-v6.cali
   ```

   NOTE: This allows Calico to be able to manage cali* interfaces on the host.
   While it prevents Network Manager from interfering.
2. Calico requires a key/value store accessible by all Calico components. On
   Kubernetes, we will configure Calico to use the Kubernetes API datastore.
3. Network requirements, open firewall for:
   * Calico networking (BGP) Bidirectional TCP 179.
   * Calico networking with VXLAN enabled Bidirectional UDP 4789.
   * Calico networking with Typha enabled Typha agent hosts Incoming TCP 5473.
4. Install Calico CRDs in order to use Kubernetes as the datastore:

   ```shell
   wget https://raw.githubusercontent.com/projectcalico/calico/v3.32.2/manifests/crds.yaml
   kubectl apply -f crds.yaml
   ```
5. Give Calico permission in the cluster.
   1. Make a ClusterRole for Calico.

      ```shell
      cd ~/manifests
      cat <<TXT | tee calico-clusterrole.yaml
      kind: ClusterRole
      apiVersion: rbac.authorization.k8s.io/v1
      metadata:
        name: calico-cni
      rules:
      # The CNI plugin needs to get pods, nodes, and namespaces.
      - apiGroups: [""]
        resources:
        - pods
        - nodes
        - namespaces
        verbs:
        - get
      # The CNI plugin patches pods/status.
      - apiGroups: [""]
        resources:
          - pods/status
        verbs:
          - patch
      # These permissions are required for Calico CNI to perform IPAM allocations.
      - apiGroups: ["crd.projectcalico.org"]
        resources:
        - blockaffinities
        - ipamblocks
        - ipamhandles
        verbs:
        - get
        - list
        - create
        - update
        - delete
      - apiGroups: ["crd.projectcalico.org"]
        resources:
        - ipamconfigs
        - clusterinformations
        - ippools
        verbs:
        - get
        - list
      TXT
      kubectl apply -f ~/manifests/calico-clusterrole.yaml
      ```
   2. Bind the cluster role to the calico-cni account.

      ```shell
      kubectl create clusterrolebinding calico-cni --clusterrole=calico-cni --user=calico-cni
      ```
6. Install `calicoctl`.

   ```shell
   wget -O calicoctl https://github.com/projectcalico/calico/releases/latest/download/calicoctl-linux-amd64
   chmod +x calicoctl
   sudo mv calicoctl /usr/local/bin/
   export KUBECONFIG="${HOME}/.kube/config"
   export DATASTORE_TYPE=kubernetes
   # Persist on restart of machine.
   cat <<TXT | tee -a ~/.bashrc
   export KUBECONFIG="${HOME}/.kube/config"
   export DATASTORE_TYPE=kubernetes
   TXT
   # test
   calicoctl get nodes
   calicoctl get ippools
   ```

   NOTE: You must run sudo with the -E flag to include your environment
   variables `sudo -E calicoctl node diags`. You may also need to downlaod this
   from your S3 proxy if you are using IPv6 only.
7. Configure an IP Pool:

   ```shell
   cd ~/manifests
   HOST_NAME="$(hostname)"
   cat <<TXT | tee calico-pool-01.yaml
   apiVersion: projectcalico.org/v3
   kind: IPPool
   metadata:
     name: ippool-vxlan-1
   spec:
     blockSize: 122
     cidr: 'fd12:3456:789a:1000::/64'
     vxlanMode: Always
     natOutgoing: true
     nodeSelector: kubernetes.io/hostname == '${HOST_NAME}'
   TXT
   calicoctl create -f calico-pool-01.yaml
   ```

8. Provision Kubernetes user account for the plugin:
   1. Make an SSL certificate signed by the cluster.
      ```shell
      cd ~/certs
      openssl req -newkey rsa:4096 \
          -keyout cni.key \
          -nodes \
          -out cni.csr \
          -subj "/CN=calico-cni"
      sudo openssl x509 -req -in cni.csr \
         -CA /etc/kubernetes/pki/ca.crt \
         -CAkey /etc/kubernetes/pki/ca.key \
         -CAcreateserial \
         -out cni.crt \
         -days 365
      sudo chown $(id -u):$(id -g) cni.crt
      ```
   2. Make a kubeconfig for calico to access the cluster.

      ```shell
      APISERVER=$(kubectl config view -o jsonpath='{.clusters[0].cluster.server}')
      kubectl config set-cluster kubernetes \
        --certificate-authority=/etc/kubernetes/pki/ca.crt \
        --embed-certs=true \
        --server=$APISERVER \
        --kubeconfig=cni.kubeconfig

      kubectl config set-credentials calico-cni \
        --client-certificate=cni.crt \
        --client-key=cni.key \
         --embed-certs=true \
         --kubeconfig=cni.kubeconfig

      kubectl config set-context default \
        --cluster=kubernetes \
        --user=calico-cni \
        --kubeconfig=cni.kubeconfig

      kubectl config use-context default --kubeconfig=cni.kubeconfig
      ```

   3. Install the kubeconfig

      ```shell
      sudo install -m 600 ~/certs/cni.kubeconfig /etc/cni/net.d/calico-kubeconfig
      ```
9. Install the plugin.

   ```shell
   curl -L -o calico https://github.com/projectcalico/cni-plugin/releases/download/v3.14.0/calico-amd64
   sudo install -m 755 calico /opt/cni/bin
   curl -L -o calico-ipam https://github.com/projectcalico/cni-plugin/releases/download/v3.14.0/calico-ipam-amd64
   sudo install -m 755 calico-ipam /opt/cni/bin
   ```
   alternatively use S3 as a proxy:

   ```shell
   cd
   aws s3 cp s3://<your-kubernetes-assets-proxy>/release-v3.32.2.tgz .
   tar -xzf release-v3.32.2.tgz
   sudo install -m 755 ~/release-v3.32.2/bin/cni/amd64/calico /opt/cni/bin
   sudo install -m 755 ~/release-v3.32.2/bin/cni/amd64/calico-ipam /opt/cni/bin
   ```
10. Configure the plugin.

    ```shell
    sudo mkdir -p /etc/cni/net.d
    cat <<TXT | sudo tee /etc/cni/net.d/10-calico.conflist
    {
      "name": "k8s-pod-network",
      "cniVersion": "0.3.1",
      "plugins": [
        {
          "type": "calico",
          "log_level": "info",
          "datastore_type": "kubernetes",
          "mtu": 1500,
          "ipam": {
              "type": "calico-ipam",
              "assign_ipv4": "false",
              "assign_ipv6": "true"
          },
          "policy": {
              "type": "k8s"
          },
          "kubernetes": {
              "kubeconfig": "/etc/cni/net.d/calico-kubeconfig"
          }
        },
        {
          "type": "portmap",
          "snat": true,
          "capabilities": {"portMappings": true}
        }
      ]
    }
    TXT
    ```
11. Install Typha
    1. Provision Certificates

       ```shell
       cd ~/certs
       openssl req -x509 -newkey rsa:4096 \
                 -keyout typhaca.key \
                 -nodes \
                 -config ~/certs/openssl-calico-typha.conf \
                 -section typhaca \
                 -out typhaca.crt \
                 -subj "/CN=Calico Typha CA" \
                 -days 365
       ```
    2. Install the CA in a ConfigMap.

       ```shell
       kubectl create configmap -n kube-system calico-typha-ca --from-file=typhaca.crt
       ```
    3. Create the Typha key and certificate signing request (CSR)

       ```shell
       # Make a Certificate Signing Request
       openssl genrsa -out ~/certs/typha.key 4096
       openssl req -new -key ~/certs/typha.key -sha256 \
            -config openssl-calico-typha.conf -section typha \
            -out ~/certs/typha.csr
       ```
    4. Sign the Typha certificate with the CA

       ```shell
       openssl x509 -req -in ~/certs/typha.csr \
                  -copy_extensions copyall \
                  -CA ~/certs/typhaca.crt \
                  -CAkey ~/certs/typhaca.key \
                  -CAcreateserial \
                  -out ~/certs/typha.crt \
                  -days 365
       ```
    5. Store the Typha key and certificate in a secret that Typha will access

       ```shell
       cd ~/certs
       kubectl create secret generic -n kube-system calico-typha-certs --from-file=typha.key --from-file=typha.crt
       ```
    6. Create a ServiceAccount that will be used to run Typha.

       ```shell
       kubectl create serviceaccount -n kube-system calico-typha
       ```
    7. Define a cluster role for Typha with permission to watch Calico datastore objects.

       ```shell
       cd ~/manifests
       cat <<TXT | tee typha-clusterrole.yaml
       kind: ClusterRole
       apiVersion: rbac.authorization.k8s.io/v1
       metadata:
         name: calico-typha
       rules:
         - apiGroups: [""]
           resources:
             - pods
             - namespaces
             - serviceaccounts
             - endpoints
             - services
             - nodes
           verbs:
             - watch
             - list
             - get
         - apiGroups: ["networking.k8s.io"]
           resources:
             - networkpolicies
           verbs:
             - watch
             - list
         - apiGroups: ["crd.projectcalico.org"]
           resources:
             - globalfelixconfigs
             - felixconfigurations
             - bgppeers
             - globalbgpconfigs
             - bgpconfigurations
             - ippools
             - ipamblocks
             - globalnetworkpolicies
             - globalnetworksets
             - networkpolicies
             - clusterinformations
             - hostendpoints
             - blockaffinities
             - networksets
           verbs:
             - get
             - list
             - watch
         - apiGroups: ["crd.projectcalico.org"]
           resources:
             #- ippools
             #- felixconfigurations
             - clusterinformations
           verbs:
             - get
             - create
             - update
       TXT
       kubectl apply -f ~/manifests/typha-clusterrole.yaml
       # Bind the ClusterRole to the ServiceAccount.
       kubectl create clusterrolebinding calico-typha --clusterrole=calico-typha --serviceaccount=kube-system:calico-typha
       ```
12. Install Deployment.

    ```shell
    cat <<TXT | tee ~/manifests/typha-deployment.yaml
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: calico-typha
      namespace: kube-system
      labels:
        k8s-app: calico-typha
    spec:
      replicas: 3
      revisionHistoryLimit: 2
      selector:
        matchLabels:
          k8s-app: calico-typha
      template:
        metadata:
          labels:
            k8s-app: calico-typha
          annotations:
            cluster-autoscaler.kubernetes.io/safe-to-evict: 'true'
        spec:
          hostNetwork: true
          tolerations:
            - key: CriticalAddonsOnly
              operator: Exists
            - operator: "Exists"
              effect: "NoExecute"
            - operator: "Exists"
              effect: "NoSchedule"
          serviceAccountName: calico-typha
          priorityClassName: system-cluster-critical
          containers:
          - image: calico/typha:v3.32.2
            name: calico-typha
            ports:
            - containerPort: 5473
              name: calico-typha
              protocol: TCP
            env:
              # Disable logging to file and syslog since those don't make sense in Kubernetes.
              - name: TYPHA_LOGFILEPATH
                value: "none"
              - name: TYPHA_LOGSEVERITYSYS
                value: "none"
              # Monitor the Kubernetes API to find the number of running instances and rebalance
              # connections.
              - name: TYPHA_CONNECTIONREBALANCINGMODE
                value: "kubernetes"
              - name: TYPHA_DATASTORETYPE
                value: "kubernetes"
              - name: TYPHA_HEALTHENABLED
                value: "true"
              # Location of the CA bundle Typha uses to authenticate calico/node; volume mount
              - name: TYPHA_CAFILE
                value: /calico-typha-ca/typhaca.crt
              # Common name on the calico/node certificate
              - name: TYPHA_CLIENTCN
                value: calico-node
              # Location of the server certificate for Typha; volume mount
              - name: TYPHA_SERVERCERTFILE
                value: /calico-typha-certs/typha.crt
              # Location of the server certificate key for Typha; volume mount
              - name: TYPHA_SERVERKEYFILE
                value: /calico-typha-certs/typha.key
            livenessProbe:
              httpGet:
                path: /liveness
                port: 9098
                host: localhost
              periodSeconds: 30
              initialDelaySeconds: 30
            readinessProbe:
              httpGet:
                path: /readiness
                port: 9098
                host: localhost
              periodSeconds: 10
            volumeMounts:
            - name: calico-typha-ca
              mountPath: "/calico-typha-ca"
              readOnly: true
            - name: calico-typha-certs
              mountPath: "/calico-typha-certs"
              readOnly: true
          volumes:
          - name: calico-typha-ca
            configMap:
              name: calico-typha-ca
          - name: calico-typha-certs
            secret:
              secretName: calico-typha-certs
    TXT
    kubectl apply -f ~/manifests/typha-deployment.yaml
    ```
13. Install Service.

    ```shell
    cat <<TXT | tee ~/manifests/typa-service.yaml
    apiVersion: v1
    kind: Service
    metadata:
      name: calico-typha
      namespace: kube-system
      labels:
        k8s-app: calico-typha
    spec:
      ports:
        - port: 5473
          protocol: TCP
          targetPort: calico-typha
          name: calico-typha
      selector:
        k8s-app: calico-typha
    TXT
    kubectl apply -f ~/manifests/typa-service.yaml
    ```
14. Test Typha is using TLS.
```shell
TYPHA_CLUSTERIP="$(kubectl get svc -n kube-system calico-typha -o jsonpath='{.spec.clusterIP}')"
curl https://[${TYPHA_CLUSTERIP}]:5473 -v --cacert ~/certs/typhaca.crt
```
14. `calico-node` container environment variables, set:
    * IP6: autodetect
    * FELIX_IPV6SUPPORT: true
    * CALICO_IPV6POOL_NAT_OUTGOING: true
    * CALICO_IPV6POOL_CIDR: <same as pod cidr passed to controller-manager>
13. You can configure Felix to program cluster routes in all cases by setting
    `programClusterRoutes` in `FelixConfiguration` to `Enabled` and
    `programClusterRoutes` in `BGPConfiguration` to `Disabled`.

    NOTE: By default, Felix programs cluster routes for VXLAN IP pools, while
    BGP distributes cluster routes for IP-in-IP pools and for pools with no
    encapsulation.
