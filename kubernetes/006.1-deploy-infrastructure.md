# Deploy Infrastructure

We need a VPC to be able to deploy our cluster nodes in AWS.

## Prerequisites

* An AWS account, while its free to make an AWS account, it requires a
  credit-card to start one.
* AWS CLI installed locally on your machine.
* Knowledge of how to log into the AWS account and navigating to the different
  services.
* Knowledge of how to configure AWS CLI to grant you access to log in from the
  CLI.
* Knowledge of using VPC, EC2, IAM, Security Groups, etc.

## Make A VPC

A Virtual Private Cloud acts as a bubble so we can control network traffic to
and from our Virtual Machines (in this case cluster nodes). The public does not
get access unless we allow it. In AWS Virtual Machines run under the EC2 service
so we'll refer to the VMs as EC2 instance going forward.

Normally you'd use IaC to set this up. But where going to do it by hand in case
this is all new to you. If you're not already familiar with the AWS console,
this can help you get acquainted with the UI and a few of the services.

1. Login to the AWS console.
2. Go to `VPC` service and add a new VPC.
   1. Click "VPC and more".
   2. Give it a name, something like "dual-stack".
   3. Set the IPv4 CIDR to `172.32.0.0/16`.
   4. Select "Amazon-provided IPv6 CIDR block".
   5. Leave tenancy at "Default".
   6. 2 AZs and 2 public and 2 private subnets.
   7. Set Egress only internet gateway to "Yes".
   8. Set NAT gateways (which cost $) to "None", we will need one but will
      manually deploy it to keep cost down.
   9. Check both boxes to "Enable DNS hostnames" and "Enable DNS resolution".
   10. For "VPC endpoints" select "S3 Gateway".
   11. Click "Create VPC".

## Make a VPC endpoint

So we can connect to EC2 instances from our local machine.

1. Click "Endpoints" from the side menu.
2. Select "EC2 Instance Connect Endpoint".
3. For "Network Settings" Select the "dual-stack" VPC.
4. For "Security groups" select the default security group.
5. For "Subnet" Select a private subnet and "DualStack".
6. Click "Create endpoint".

NOTE: Remember the subnet you selected, you'll need it later when you deploy
your EC2 instance (control plane node) to it later.

### Make IAM Policies

These will be used to grant the EC2 machines the ability to perform needed
actions in the AWS account. Like spin up a Load Balancer, or pull images from 
the AWS private ECRs.

1. Go to IAM service and click "Policies" on the left navigation.
2. Click the "Create Policy" button.
3. Under "Policy Editor" select "JSON".
4. Paste this policy, then click the "Next" button:

   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Effect": "Allow",
         "Action": [
           "ec2:DescribeInstances",
           "ec2:DescribeRegions",
           "ecr:GetAuthorizationToken",
           "ecr:BatchCheckLayerAvailability",
           "ecr:GetDownloadUrlForLayer",
           "ecr:GetRepositoryPolicy",
           "ecr:DescribeRepositories",
           "ecr:ListImages",
           "ecr:BatchGetImage"
         ],
         "Resource": "*"
       }
     ]
   }
   ```
5. Name it "ecr-credentials-provider", then click the "Create Policy" button.
6. Repeat steps 2-5 to make a new IAM managed policy named `amazon-vpc-cni-k8s`
   and paste in the [amazon-vpc-cni-k8s-iam-policy.json] in the `samples`
   folder. For the description put `The Amazon VPC CNI plugin requires IAM
   policies to manage IP addresses on EC2 instances on-behalf of users.`.
7. Download the IAM policy to be attached to the instance profile of all nodes:
   ```shell
   curl -L -o iam-policy.json https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/v3.0.0/docs/install/iam_policy.json
   ```
8. Repeat steps 2-5 to make a new IAM managed policy named
   `aws-load-balancer-controller` and paste in the contents from step 7. Give
   it a description `AWS load balancer controller`.

## Make IAM Roles

1. Go to IAM service.
2. On the left navigation select "Roles."
3. Click the "Create Role" button.
4. Select "AWS Service.", Use case select "EC2", the click the "Next" button.
5. Under Add Permissions, search for and check the following
   * ecr-credentials-provider
6. Click the "Next" button.
7. Set Role name to `k8s-control-plane`, the click the "Create Role" button. 
8. On the left navigation select "Roles."
9. Click the "Create Role" button.
10. Select "AWS Service.", Use case select "EC2", the click the "Next" button.
11. Under Add Permissions, search for and check the following
    * ecr-credentials-provider
12. Click the "Next" button.
13. Set Role name to `k8s-worker`, the click the "Create Role" button. 

You should now have 2 roles, 1 for the control planes and 1 for worker nodes.

## Configure Subnets

1. For Auto-assign IP settings check:
    * Enable auto-assign IPv6 address
    * Enable auto-assign public IPv4 address
2. Set Resource-based name (RBN) settings:
    * Check "Enable resource name DNS A record on launch"
    * Check "Enable resource name DNS AAAA record on launch"
    * For Hostname type select "Resource name"
3. Check "DNS64 settings"
   NOTE: If you plan to deploy an IPv6 Cluster, then make sure this
   option is left unchecked.
4. Click "Save"

## Required Resource Tagging

This is an additional requirements for non-EKS clusters.

We'll need to manually tag subnets so they are picked up by the AWS
Controller Manager. Which ensure subnets are tagged appropriately for
auto-discovery to work.

For IP targets, Pods must have IPs from the VPC subnets. We'll configure the
[amazon-vpc-cni-k8s] plugin for this purpose.

Let's add tags to each resource in our VPC:

1. Public subnets get a tag: `kubernetes.io/role/elb` set to `1`.
2. Private subnets get a tag: `kubernetes.io/role/internal-elb` set to `1`.
3. Both subnet types get a tag `kubernetes.io/cluster/<cluster-name>` set to
   `owned`.
4. Each EC2 instance gets a tag `kubernetes.io/cluster/<cluster-name>`. This is
   a requirement for the AWS Cloud Controller manager.

NOTE: Use "owned" if resources are owned and managed by our cluster. Or
"shared" if resources are shared between clusters, and should not be destroyed
if the cluster is destroyed. Since our cluster will deploy it own Load Balancers
we use "owned."

If you did not set a cluster name, then the default cluster name is
"kubernetes". So replace `<cluster-name>` with `kubernetes`.

## Step 3: Network configuration

Your node security group must permit incoming traffic on TCP port `9443` from
the Kubernetes control plane. This is needed for webhook access.
