# Cluster Install

## Prerequisites

You need to choose which IP CIDR ranges you want to use for IPv4 and also
IPv6 if your going dual stack. The ones provided here have been tested with
local and cloud installs and are provided as defaults. They are private class
for IPv4 and global unicast for IPv6.

```text
IPv6 POD network:     fd12:3456:789a:1000::/56
IPv6 Service Network: fd12:3456:789a:2000::/112
IPv4 POD network:     10.244.0.0/16
IPv4 Service Network: 10.96.0.0/16
```

NOTE: For practice, you can generate a **ClusterConfiguration** object with
default values by running the following command, then making similar changes
as seen in the example kubeadm config below.

```shell
kubeadm config print init-defaults --component-configs KubeletConfiguration | tee kubeadm-init-config.yaml
```

Let's begin installing the cluster on the control plane.

For additional help when you get stuck, see
[Customizing components with the kubeadm API].

1. Log into the control plane with `vagrant ssh control-plane-01`.
2. Modify the configuration to include the IPv6/IPv4 CIDRs, advertise
   address, and control-plane DNS endpoint of your choosing like so:
   ```shell
   cat <<TXT | tee kubeadm-init-config.yaml
   apiVersion: kubeadm.k8s.io/v1beta4
   kind: InitConfiguration
   localAPIEndpoint:
     advertiseAddress: "fd00:192:168:56::11"
     bindPort: 6443
   nodeRegistration:
     kubeletExtraArgs:
     - name: node-ip
       value: fd00:192:168:56::11,192.168.56.11
   ---
   apiVersion: kubeadm.k8s.io/v1beta4
   kind: ClusterConfiguration
   kubernetesVersion: 1.37.0
   networking:
     dnsDomain: cluster.local
     podSubnet: fd12:3456:789a:1000::/56,10.244.0.0/16
     serviceSubnet: fd12:3456:789a:2000::/112,10.96.0.0/16
   # For now, you can add a hosts file entry so that control-plane resolves correctly.
   controlPlaneEndpoint: control-plane
   apiServer:
     # When you set the advertiseAddress to a non-loopback address, you must add the loopback address to the certSANs list.
     certSANs:
     - control-plane
     - control-plane-01
     - ::1
     - 0:0:0:0:0:0:0:1
     - fd00:192:168:56::11
     - 127.0.0.1
     - 192.168.56.11
     extraArgs:
     - --enable-aggregator-routing=true
   ---
   apiVersion: kubeadm.k8s.io/v1beta3
   kind: KubeletConfiguration
   rotateCertificates: true
   serverTLSBootstrap: true
   ```

   NOTE: Setting the `advertiseAddress` to an IPv6 address will make the
   cluster an **IPv6 Primary Cluster**. Listing both IPv6 and IPv4 CIDRs for
   `podSubnet` and `serviceSubnet` will make it a "DualStack" cluster, and
   assign IPv6 and IPv4 addresses to each Pod.

   NOTE: Setting option `rotateCertificates: true` is to allow autorotation
   of the certificate key-pair before they expire. Then we have it generate
   a serving TLS certificate with the correct SANs by turning on
   `serverTLSBootstrap: true`. This ensures that a new `kubelet` server
   certificate is generated with critical SANs listing the hostname and IP.

   You can produce the manifest that `kubeadm` would generate by running:

   ```shell
   kubeadm init phase addon coredns --print-manifest --config kubeadm-init-config.yaml
   ```
3. Start the cluster installation:

   ```shell
   sudo kubeadm config images pull
   sudo kubeadm init --v=5 --config kubeadm-init-config.yaml
   ```

   NOTE: Typically this is an excellent time to back up the CAs that kubeadm
   generated. You can get away with just the
   `/etc/kubernetes/pki/ca.{key,crt}` files because you can then use kubeadm
   to remake all the others. But it is just as easy to just back up the
   entire `/etc/kubernetes/pki` directory.
4. Verify the `kubelet` has a serving certificate, and it has the correct
   SANs:

   ```shell
   sudo openssl x509 -text -noout -in /var/lib/kubelet/pki/kubelet-server-current.pem
   ```

   NOTE: It should have the hostname and IPs of the network interface used
   for the cluster. The IP should be the one specified in the kubelet
   configuration or the IP selected as primary for the cluster.
   If not, you may need to list CSRs with `kubectl get csr`, then approve
   with `kubectl certificate approve <csr-name>`. But this requires access to
   the cluster, which we do in the next step.
