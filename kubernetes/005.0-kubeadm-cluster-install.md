# kubeadm Cluster Install

## You Should Know kubeadm Reset

`kubeadm` offers a vast amount of options to configure your cluster,
which can backfire and allow you to pick incompatible options. To counter this
simply learn how to reset/delete the cluster so you can begin anew without
having to wipe the node.

Should you make a mistake, you reset (delete) your cluster like so:

```shell
# 1. Graceful kube-apiserver shutdown
sudo apt install -y yq
sudo yq -iy '.spec.containers[0].command = []' /etc/kubernetes/manifests/kube-apiserver.yaml
timeout 60 sh -c 'while pgrep kube-apiserver >/dev/null; do sleep 1; done' || true
# 2. Cleanup the cluster.
sudo kubeadm reset -f kubeadm-init-config.yaml
# 3. Cleanup of network traffic rules.
sudo docker run --privileged --rm registry.k8s.io/kube-proxy:v1.34.6 sh -c "kube-proxy --cleanup && echo DONE"
# 4. Cleanup of CNI configuration.
sudo rm -rf /etc/cni/net.d
# 5. Cleanup of $HOME/.kube.
rm -rf $HOME/.kube
```

NOTE: Make sure to select the correct version of `kube-proxy` for your cluster.

## Cluster Install

1. You need to choose which IP CIDR ranges you want to use for IPv4 and also
   IPv6 if your going dual stack. The ones provided here are from examples in
   the Kubernetes documentation, which are private class for IPv4 and
   global unicast for IPv6:
   ```text
   IPv4 POD network:     10.244.0.0/16
   IPv4 Service Network: 10.96.0.0/16
   IPv6 POD network:     fd12:3456:789a:1000::/56
   IPv6 Service Network: fd12:3456:789a:2000::/112
   ```
2. Begin installing the cluster on the control plane:
    1. Log into the control plane with `ssh vagrant@control-plane-01`.
    2. Generate a **ClusterConfiguration** object with default values by running
       `kubeadm config print init-defaults > kubeadm-config.yaml`.
    3. Modify the configuration to include the IPv4/IPv6 CIDRs, advertise
       address, and control-plane DNS endpoint of your choosing like so:
       ```yaml
       ---
       apiVersion: kubeadm.k8s.io/v1beta4
       kind: InitConfiguration
       localAPIEndpoint:
         advertiseAddress: 2000:192:168:56::11
         bindPort: 6443
       nodeRegistration:
         kubeletExtraArgs:
           - name: node-ip
             value: 2000:192:168:56::11,192.168.56.11
       ---
       apiVersion: kubeadm.k8s.io/v1beta4
       kind: ClusterConfiguration
       kubernetesVersion: 1.34.0
       networking:
         dnsDomain: cluster.local
         podSubnet: fd12:3456:789a:1000::/56,10.244.0.0/16
         serviceSubnet: fd12:3456:789a:2000::/112,10.96.0.0/16
       # For now, you can add a hosts file entry so that control-plane resolves correctly.
       controlPlaneEndpoint: control-plane
       apiServer:
         certSANs:
          - ::1 # When you set the advertiseAddress to a non-loopback address, you must add the loopback address to the certSANs list.
          - 0:0:0:0:0:0:0:1
          - 127.0.0.1
          - 2000:192:168:56::11
          - 192.168.56.11
          - control-plane
       ```
    4. start the cluster installation:
       ```shell
       sudo kubeadm config images pull
       sudo kubeadm init --config kubeadm-config.yaml
       ```

       NOTE: The following resources were used to piece all this together:
       [Creating a cluster with kubeadm].

       NOTE: Typically this is an excellent time to back up the CAs that kubeadm
       generated. You can get away with just the
       `/etc/kubernetes/pki/ca.{key,crt}` files because you can then use kubeadm
       to remake all the others. But it is just as easy to just back up the
       entire `/etc/kubernetes/pki` directory.
