# Gateway API

Gateway API is focused on L4 and L7 routing in Kubernetes.

It allows you to combine multiple services (mesh) behind a single endpoint.
It receives all incoming traffic and directs (proxies) them to the correct
services.

You may hear the terms "North", "South", "East", and "West", in this context,
refers to an HTTP request coming into the "Gateway" (the North) and being sent
to a Service (the South). "East and West" just refer to all the services mapped
to by HTTPRoute and GRPCRoute's, if you were to imagine them laid out from
right to left in a diagram.

Most of the configuration in this API is contained in the Routing layer. These
protocol-specific resources (HTTPRoute, GRPCRoute, etc).

For in-depth info see [Introduction]

The big idea here is to use a Gateway to mesh a bunch of services together into
something useful for an audience. The convenience is to keep them from having
to interface with each service individually. The trade-off is that they now
have this extra layer, which may reduce speed of request/response times, but
can greatly ease interaction with many services.
