# Add Metrics Server

Metrics Server collects resource metrics from Kubelets and exposes them in
`kube-apiserver` through the API, it provides, for use by Horizontal
Pod Autoscaler and Vertical Pod Autoscaler. It can also be accessed by
`kubectl top`, making it easier to debug autoscaling pipelines.

NOTE: Metrics Server is meant only for autoscaling purposes.

Read more about it at [metrics-server]. Also, see [metrics-server CLI help].

## Step 1 Generate Certificate

This certificate will be used in the [Authentication Flow] for Extended API's.

1. Backup the `kube-apiserver.yaml` manifest and `front-pProxy-ca.{crt,key}`
   files:

   ```shell
   sudo cp "${cert_dir}/${i}.key" ~/backups/${i}-$(date +%F).key
   sudo cp "${cert_dir}/${i}.crt" ~/backups/${i}-$(date +%F).crt
   sudo cp /etc/kubernetes/manifest/kube-apiserver.yaml ~/backups/kube-apiserver-$(date +%F).yaml
   ls ~/backups
   ```
2. Modify the `/etc/kubernetes/manifest/kube-apiserver.yaml` and add options
   `--enable-aggregator-routing=true` and
   `--requestheader-allowed-names=front-proxy-client,metrics-server`.
   NOTE: Once you edit the `kube-apiserver.yaml` file, it and other components
   will restart. This should take about a minute. Watch it closely.
3. Make a workspace on the `control-plane-01`:

   ```shell
   mkdir -p ~/certs && cd ~/certs
   sudo cp /etc/kubernetes/pki/front-proxy-ca.key ./
   sudo chown vagrant:vagrant front-proxy-ca.key
   ```
4. Make an OpenSSL config to aid in generated the key/cert pair:

   ```shell
   mkdir -p ~/certs && cd ~/certs
   cat <<TXT | tee openssl-metrics-server.conf
   [ server ]
   distinguished_name = server_dn
   req_extensions     = server_ext
   prompt             = no

   [ server_dn ]
   CN = metrics-server
   O  = system:metrics-server

   [ server_ext ]
   basicConstraints = CA:TRUE
   extendedKeyUsage = serverAuth
   keyUsage         = critical, digitalSignature, keyEncipherment
   subjectAltName   = DNS:control-plane, DNS:control-plane-01, IP:127.0.0.1, IP:192.168.56.11, IP:[2000:192:168:56::11]

   [ proxy_client ]
   distinguished_name = proxy_client_dn
   req_extensions     = proxy_client_ext
   prompt             = no

   [ proxy_client_dn ]
   CN = metrics-server
   O  = system:aggregated-metrics-reader

   [ proxy_client_ext ]
   basicConstraints = CA:FALSE
   extendedKeyUsage = clientAuth
   keyUsage         = critical, digitalSignature, keyEncipherment
   subjectAltName   = @proxy_client_alt_names

   [ proxy_client_alt_names ]
   DNS.1 = control-plane
   DNS.2 = control-plane-01
   DNS.3 = worker-01
   DNS.4 = worker-02
   DNS.5 = front-proxy-ca
   IP.1 = 192.168.56.11
   IP.2 = 2000:192:168:56::11
   IP.3 = 192.168.56.21
   IP.4 = 2000:192:168:56::21
   IP.5 = 192.168.56.22
   IP.6 = 2000:192:168:56::22

   # Remake the Front Proxy CA with added DNS and IPs.
   [ front-proxy-ca ]
   default_bits       = 2048
   default_md         = sha256
   prompt             = no
   x509_extensions    = front-proxy-ca_ext
   distinguished_name = front-proxy-ca_dn
   prompt             = no

   [ front-proxy-ca_dn ]
   CN = front-proxy-ca

   [ front-proxy-ca_ext ]
   basicConstraints = critical, CA:TRUE
   keyUsage         = critical, digitalSignature, keyEncipherment, keyCertSign, cRLSign
   subjectAltName   = @proxy_client_alt_names

   # A client certificate for the front proxy client.
   [ front-proxy-client ]
   distinguished_name = front-proxy-client_dn
   prompt             = no
   req_extensions     = v3_extensions

   [ front-proxy-client_dn ]
   CN = front-proxy-client

   [ v3_extensions ]
   basicConstraints = critical, CA:FALSE
   extendedKeyUsage = clientAuth
   keyUsage         = critical, digitalSignature, keyEncipherment
   TXT
   ```
5. Update the `front-proxy-ca` with new DNS.

   ```shell
   CERT_BITS=2048
   CERT_DAYS=365
   cert_dir=/etc/kubernetes/pki
   CERT_CONF="openssl-metrics-server.conf"
   CERT_NAME="front-proxy-client-metrics-server"

   # Generate a new front-proxy-ca.crt using the existing key.
   i="front-proxy-ca"
   openssl req -x509 -new -noenc \
       -key "${i}.key" -days ${CERT_DAYS} \
       -config ${CERT_CONF} -section ${i} \
       -out "${i}.crt"

   # Make a new front-proxy-client.crt
   i="front-proxy-client"
   sudo openssl req -new -key "${cert_dir}/${i}.key" -sha256 \
       -config "${CERT_CONF}" -section ${i} \
       -out "${i}.csr"
   sudo openssl x509 -req -days ${CERT_DAYS} -in "${i}.csr" \
       -copy_extensions copyall \
       -CAkey "${cert_dir}/front-proxy-ca.key" \
       -sha256 -CA "${cert_dir}/front-proxy-ca.crt" \
       -CAcreateserial \
       -out "${i}.crt"
   ```
6. Make a front proxy client cert for the `metrics-server`:

   ```shell
   # Make key
   openssl genrsa -out "${CERT_NAME}.key" ${CERT_BITS}
   # Make a csr.
   openssl req -new -key "${CERT_NAME}.key" -sha256 \
       -config "${CERT_CONF}" -section "proxy_client" \
       -out "${CERT_NAME}.csr"
   # Make a certificate.
   sudo openssl x509 -req -days ${CERT_DAYS} -in "${CERT_NAME}.csr" \
       -copy_extensions copyall \
       -CAkey "front-proxy-ca.key" \
       -sha256 -CA "front-proxy-ca.crt" \
       -CAcreateserial \
       -out "${CERT_NAME}.crt"
   ```

   NOTE: Theory:
   1. Check that the DNS names need to be IPs in the cert instead.
      1. No, you cannot use a DNS name as an IP on a cert. It will throw an error.
   2. Verify what cert requirements are for '--tls-cert-file` and `--tls-private-key-file'
      1. According to the Kubernetes Docs, the keyusage must be a clientAuth and
         signed with the `front-proxy-ca`.
   3. Do I need to add DNS names to the front-proxy-ca?
      4. This requires a new `front-proxy-ca.crt`, which will then require a new
         `front-proxy-client-ca.{crt,key}` pair. Then you can generate a new
         `metrics-server` certificate from the `front-proxy-ca.crt` as well.
7. Copy certs and keys into place on `control-plane-01` and both worker nodes:
   ```shell
   rm -f *.{csr,srl,conf}
   sudo cp -r ~/certs/* /etc/kubernetes/pki
   scp -r ~/certs/* worker-01:~/certs
   scp -r ~/certs/* worker-02:~/certs
   ```
8. Login to each worker node via `ssh worker-01` and `ssh worker-02` and move
   the certs into place:

   ```shell
   sudo install -m 644 ~/certs/front-proxy* /etc/kubernetes/pki
   sudo ls -la /etc/kubernetes/pki/
   ```

## Step 2 Generate kubelet Certificate

Generate a certificate for the metrics server to authenticate with each
`kubelet` in the cluster.

1. Generate a key and certificate (signed by the Kubernetes CA) for each node's
   `kubelet` to use.
   ```shell
   getKubeletIps () {
       iface=${1}
       export IPV4=$(ip -4 addr show scope global dev ${iface} | grep "inet\b" | awk '{print $2}' | cut -d/ -f1)
       export IPV6=$(ip -6 addr show scope global dev ${iface} | grep "inet6\b" | awk '{print $2}' | cut -d/ -f1)
   }
   CERT_BITS=2048
   CERT_DAYS=365
   cert_dir=/etc/kubernetes/pki
   KUBELET_CONF="openssl-kubelet.conf"
   KEY_PAIR="metrics-server-kubelet"

   cp /vagrant/${KUBELET_CONF}.tmpl .

   # get IPs
   getKubeletIps "enp0s8"

   # more environment setup
   export NODE_NAME="$(hostname)"
   export NODE_IPV4=${IPV4}
   export NODE_IPV6=${IPV6}

   # generate a new kubelet OpenSSL configuration.
   envsubst < openssl-kubelet.conf.tmpl > openssl-kubelet.conf

   # generate a key
   sudo openssl genrsa -out "${KEY_PAIR}.key" ${CERT_BITS}

   # make a CSR
   sudo openssl req -new -key "${KEY_PAIR}.key" -sha256 \
       -config "${KUBELET_CONF}" -section "metrics_server" \
       -out "${KEY_PAIR}.csr"
   # Use the cluster CA to sign the CSR and make a certificate.
   sudo openssl x509 -req -days ${CERT_DAYS} -in "${KEY_PAIR}.csr" \
       -copy_extensions copyall \
       -CAkey "${cert_dir}/ca.key" \
       -sha256 -CA "${cert_dir}/ca.crt" \
       -CAcreateserial \
       -out "${KEY_PAIR}.crt"
   # move into place
   sudo cp ${KEY_PAIR}.crt /etc/kubernetes/pki/metrics-server-kubelet.crt
   sudo cp ${KEY_PAIR}.key /etc/kubernetes/pki/metrics-server-kubelet.key
   sudo rm ${KEY_PAIR}.csr
   mkdir -p /tmp/certs
   cp  ${KEY_PAIR}.crt /tmp/certs
   sudo cp ${KEY_PAIR}.key /tmp/certs
   sudo chmod 0644 -R /tmp/certs/*
   ```
2. Test:
   ```shell
   sudo curl -v --cacert /etc/kubernetes/pki/ca.crt \
     --cert /etc/kubernetes/pki/apiserver-kubelet-client.crt \
     --key /etc/kubernetes/pki/apiserver-kubelet-client.key \
     https://control-plane-01:10250/metrics

   sudo curl -v --cacert /etc/kubernetes/pki/ca.crt \
     --cert /tmp/certs/metrics-server-kubelet.crt \
     --key /tmp/certs/metrics-server-kubelet.key \
     https://control-plane-01:10250/metrics
   ```
## Install

Before deploying metrics server, note the following:

`--kubelet-preferred-address-types` - The priority of node address types used when determining an address for connecting to a particular node (default [Hostname,InternalDNS,InternalIP,ExternalDNS,ExternalIP])
`--kubelet-insecure-tls` - Do not verify the CA of serving certificates presented by Kubelets. For testing purposes only.
`--requestheader-client-ca-file` - Specify a root certificate bundle for verifying client certificates on incoming requests.

1. Drop back into the `control-panel-01` terminal and apply the `metrics-server`
   manifest:
   ```shell
   wget -O metrics-server.yaml https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
   vi metrics-server.yaml
   ```

   Edit the Deployment section to add these options along with volumes for the
   following files:
   ```yaml
        - --requestheader-client-ca-file=/etc/kubernetes/pki/front-proxy-ca.crt
        - --tls-cert-file=/etc/kubernetes/pki/front-proxy-client-metrics-server.crt
        - --tls-private-key-file=/etc/kubernetes/pki/front-proxy-client-metrics-server.key
        - --kubelet-certificate-authority=/etc/kubernetes/pki/ca.crt
        - --kubelet-client-certificate=/etc/kubernetes/pki/metrics-server-kubelet.crt
        - --kubelet-client-key=/etc/kubernetes/pki/metrics-server-kubelet.key
   ```

   NOTE: The options `--requestheader-client-ca-file`, `--tls-cert-file`, and
   `--tls-private-key-file` file are for connecting to the `kube-apiserver` API.
   While `--kubelet-client-certificate`, `--kubelet-client-key`, and
   `--kubelet-certificate-authority` are use for ???.
   ```shell
   kubectl apply -f metrics-server.yaml
   ```

NOTE: You can easily add a sidecar for looking around the Pod:

```yaml
kubectl debug -it --image=busybox --target=metrics-server -n kube-system
```

NOTE: To see all options for the metrics server, you can run

```shell
docker run --rm k8s.gcr.io/metrics-server/metrics-server:v0.8.1 --help
```
