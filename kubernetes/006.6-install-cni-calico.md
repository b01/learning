# Install CNI Calico

This installs [Calico The Hard Way].

## Summary

Setting up Calico manually can be very vexing because of the sheer amount
of options spread throughout the documentation. If you use the automated setup
that hides all this, then you won't know or understand a good amount of it. It
will be even harder to troubleshoot. This is why I've opted in to manually
setting up Calico the hard way. I plan to do it locally on VMs and in the Cloud.

## Installing on AWS

Normally we'd use Amazon VPC CNI plugin. But were running into issues using it
in IPv6 only mode. Plus there are other issue you'd want to watch out for. So
we are going to install Calico as our Network CNI plugin instead. We will use
the options:

| Policy | IPAM   | CNI    | Overlay | Routing |
|--------|--------|--------|---------|---------|
| Calico | Calico | Calico | VXLAN   | Calico  |

For more details see [Determine best networking option: AWS].

It's also working reviewing
[Configure Kubernetes control plane to operate over IPv6].

## Get Started

1. Configure NetworkManager.

   ```shell
   cat <<TXT | sudo tee -E /etc/NetworkManager/conf.d/calico.conf
   [keyfile]
   unmanaged-devices=interface-name:cali*;interface-name:tunl*;interface-name:vxlan.calico;interface-name:vxlan-v6.calico;interface-name:wireguard.cali;interface-name:wg-v6.cali
   ```

   NOTE: This allows Calico to be able to manage cali* interfaces on the host.
   While it prevents Network Manager from interfering.
2. Calico requires a key/value store accessible by all Calico components. On
   Kubernetes, we will configure Calico to use the Kubernetes API datastore.
3. Network requirements, open firewall for:
   * Calico networking (BGP) Bidirectional TCP 179.
   * Calico networking with VXLAN enabled Bidirectional UDP 4789.
   * Calico networking with Typha enabled Typha agent hosts Incoming TCP 5473.
4. Install Calico CRDs in order to use Kubernetes as the datastore:

   ```shell
   mkdir -p ~/manifests
   wget -o ~/manifests/crds-v3-projectcalico.org.yaml https://raw.githubusercontent.com/projectcalico/calico/v3.32.2/manifests/v3_projectcalico_org.yaml
   kubectl apply -f ~/manifests/crds-v3-projectcalico.org.yaml
   ```

   NOTE: Be careful, there are places in the docs refer to the old `v1`
   crds.yaml.
   See https://docs.tigera.io/calico/latest/operations/native-v3-crds.
5. Give Calico permission in the cluster.
   1. Make a ClusterRole for Calico CNI plugin.

      ```shell
      cd ~/manifests
      cat <<TXT | tee calico-clusterrole.yaml
      kind: ClusterRole
      apiVersion: rbac.authorization.k8s.io/v1
      metadata:
        name: calico-cni
      rules:
      # The CNI plugin needs to get pods, nodes, and namespaces.
      - apiGroups: [""]
        resources:
        - pods
        - nodes
        - namespaces
        verbs:
        - get
      # The CNI plugin patches pods/status.
      - apiGroups: [""]
        resources:
          - pods/status
        verbs:
          - patch
      # These permissions are required for Calico CNI to perform IPAM allocations.
      - apiGroups: ["crd.projectcalico.org"]
        resources:
        - blockaffinities
        - ipamblocks
        - ipamhandles
        verbs:
        - get
        - list
        - create
        - update
        - delete
      - apiGroups: ["crd.projectcalico.org"]
        resources:
        - ipamconfigs
        - clusterinformations
        - ippools
        verbs:
        - get
        - list
      TXT
      kubectl apply -f ~/manifests/calico-clusterrole.yaml
      ```
   2. Bind the cluster role to the calico-cni account.

      ```shell
      kubectl create clusterrolebinding calico-cni --clusterrole=calico-cni --user=calico-cni
      ```
## Install `calicoctl`.

1. Download `calicoctl`:

   ```shell
   wget -O calicoctl https://github.com/projectcalico/calico/releases/latest/download/calicoctl-linux-amd64
   chmod +x calicoctl
   sudo mv calicoctl /usr/local/bin/
   export KUBECONFIG="${HOME}/.kube/config"
   export DATASTORE_TYPE=kubernetes
   # Persist on restart of machine.
   cat <<TXT | tee -a ~/.bashrc
   export KUBECONFIG="${HOME}/.kube/config"
   export DATASTORE_TYPE=kubernetes
   TXT
   # test
   calicoctl get nodes
   calicoctl get ippools
   ```

   NOTE: You must run sudo with the -E flag to include your environment
   variables `sudo -E calicoctl node diags`. You may also need to downlaod this
   from your S3 proxy if you are using IPv6 only.
2. Configure an IP Pool:

   ```shell
   cat <<TXT | tee ~/manifests/calico-pool-01.yaml
   apiVersion: projectcalico.org/v3
   kind: IPPool
   metadata:
     name: pool1
   spec:
     cidr: 'fd12:3456:789a:1000::/64'
     vxlanMode: Always
     natOutgoing: true
     nodeSelector: all()
   TXT
   calicoctl create -f ~/manifests/calico-pool-01.yaml
   ```

3. Provision Kubernetes user account for the plugin:
   1. Make an SSL certificate signed by the cluster.
      ```shell
      cd ~/certs
      openssl req -newkey rsa:4096 \
          -keyout cni.key \
          -nodes \
          -out cni.csr \
          -subj "/CN=calico-cni"
      sudo openssl x509 -req -in cni.csr \
         -CA /etc/kubernetes/pki/ca.crt \
         -CAkey /etc/kubernetes/pki/ca.key \
         -CAcreateserial \
         -out cni.crt \
         -days 365
      sudo chown $(id -u):$(id -g) cni.crt
      ```
   2. Make a kubeconfig for calico to access the cluster.

      ```shell
      APISERVER=$(kubectl config view -o jsonpath='{.clusters[0].cluster.server}')
      kubectl config set-cluster kubernetes \
        --certificate-authority=/etc/kubernetes/pki/ca.crt \
        --embed-certs=true \
        --server=$APISERVER \
        --kubeconfig=cni.kubeconfig

      kubectl config set-credentials calico-cni \
        --client-certificate=cni.crt \
        --client-key=cni.key \
         --embed-certs=true \
         --kubeconfig=cni.kubeconfig

      kubectl config set-context default \
        --cluster=kubernetes \
        --user=calico-cni \
        --kubeconfig=cni.kubeconfig

      kubectl config use-context default --kubeconfig=cni.kubeconfig
      ```

   3. Install the kubeconfig

      ```shell
      sudo install -m 600 ~/certs/cni.kubeconfig /etc/cni/net.d/calico-kubeconfig
      ```
4. Install the plugin.

   ```shell
   curl -L https://github.com/projectcalico/calico/releases/download/v3.32.2/release-v3.32.2.tgz
   tar -xzf release-v3.32.2.tgz
   sudo install -m 755 ~/release-v3.32.2/bin/cni/amd64/calico /opt/cni/bin
   sudo install -m 755 ~/release-v3.32.2/bin/cni/amd64/calico-ipam /opt/cni/bin
   ```
   alternatively use S3 as a proxy:

   ```shell
   cd
   aws s3 cp s3://<your-kubernetes-assets-proxy>/release-v3.32.2.tgz .
   tar -xzf release-v3.32.2.tgz
   sudo install -m 755 ~/release-v3.32.2/bin/cni/amd64/calico /opt/cni/bin
   sudo install -m 755 ~/release-v3.32.2/bin/cni/amd64/calico-ipam /opt/cni/bin
   ```
5. Configure the plugin.

   ```shell
   sudo mkdir -p /etc/cni/net.d
   cat <<TXT | sudo tee /etc/cni/net.d/10-calico.conflist
   {
     "name": "k8s-pod-network",
     "cniVersion": "0.3.1",
     "plugins": [
       {
         "type": "calico",
         "log_level": "info",
         "datastore_type": "kubernetes",
         "mtu": 1500,
         "ipam": {
             "type": "calico-ipam",
             "assign_ipv4": "false",
             "assign_ipv6": "true"
         },
         "policy": {
             "type": "k8s"
         },
         "kubernetes": {
             "kubeconfig": "/etc/cni/net.d/calico-kubeconfig"
         }
       },
       {
         "type": "portmap",
         "snat": true,
         "capabilities": {
           "portMappings": true
         }
       }
     ]
   }
   TXT
   ```

## Configuring Felix

This information was gathered from [Configuring Felix].

```shell
cat <<TXT | tee ~/manifests/calico-felix.yaml
apiVersion: projectcalico.org/v3
kind: FelixConfiguration
metadata:
  name: default
spec:
  ipv6Support: true
  vxlanEnabled: true
  allowIPIPPacketsFromWorkloads: false
  allowVXLANPacketsFromWorkloads: true
  ipipEnabled: false
  awsSrcDstCheck: "Disable"
TXT
calicoctl apply -f ~/manifests/calico-felix.yaml
calicoctl create felixconfiguration -f ~/manifests/calico-felix.yaml

calicoctl get felixconfiguration default -o yaml --export > felix.yaml
```

NOTE: Setting `awsSrcDstCheck` to `Disable` will automatically disable
source-destination-check on EC2 instances in a cluster, provided necessary
IAM roles and policies are set. One of the policies assigned to IAM role of
cluster nodes must contain a statement similar to the following:

```json
{
    "Effect": "Allow",
        "Action": [
            "ec2:DescribeInstances",
            "ec2:ModifyNetworkInterfaceAttribute"
        ],
    "Resource": "*"
}
```

## Provision RBAC

Next we make the `calico-node` ClusterRole. We can use it for `calico-node`
and `calico-typha`, since they officially use the same role.
[Calico The Hard Way] docs still have them separate. That is not how it is done
at the time of writing.

You can still find remnants of the `calico-typha` Service Account in the
[calico repo], but the ClusterRole itself does not exist. You can clearly see
here at [calico-typha.yaml#L13316] and also here [calico-typha.yaml#L81] that
`calico-typha` uses the `calico-node` service account.

1. Create the ServiceAccount that calico/node will run as

   ```shell
   kubectl create serviceaccount -n kube-system calico-node
   ```

## Install Typha

1. Provision Certificates

   ```shell
   openssl req -x509 -newkey rsa:4096 \
             -keyout ~/certs/typhaca.key \
             -nodes \
             -config ~/certs/openssl-calico-typha.conf \
             -section ~/certs/typhaca \
             -out ~/certs/typhaca.crt \
             -subj "/CN=Calico Typha CA" \
             -days 365
   ```
2. Install the CA in a ConfigMap.

   ```shell
   kubectl create configmap -n kube-system calico-typha-ca --from-file=typhaca.crt
   ```
3. Create the Typha key and certificate signing request (CSR)

   ```shell
   # Make a Certificate Signing Request
   openssl genrsa -out ~/certs/typha.key 4096
   openssl req -new -key ~/certs/typha.key -sha256 \
        -config openssl-calico-typha.conf -section typha \
        -out ~/certs/typha.csr
   ```
4. Sign the Typha certificate with the CA

   ```shell
   openssl x509 -req -in ~/certs/typha.csr \
              -copy_extensions copyall \
              -CA ~/certs/typhaca.crt \
              -CAkey ~/certs/typhaca.key \
              -CAcreateserial \
              -out ~/certs/typha.crt \
              -days 365
   ```
5. Store the Typha key and certificate in a secret that Typha will access

   ```shell
   cd ~/certs
   kubectl create secret generic -n kube-system calico-typha-certs --from-file=typha.key --from-file=typha.crt
   ```
6. Create a ServiceAccount that will be used to run Typha.

   ```shell
   kubectl create serviceaccount -n kube-system calico-typha
   ```
7. Install Deployment.

   ```shell
   cat <<TXT | tee ~/manifests/typha-deployment.yaml
   apiVersion: apps/v1
   kind: Deployment
   metadata:
     name: calico-typha
     namespace: kube-system
     labels:
       k8s-app: calico-typha
   spec:
     replicas: 3
     revisionHistoryLimit: 2
     selector:
       matchLabels:
         k8s-app: calico-typha
     template:
       metadata:
         labels:
           k8s-app: calico-typha
         annotations:
           cluster-autoscaler.kubernetes.io/safe-to-evict: 'true'
       spec:
         hostNetwork: true
         tolerations:
           - key: CriticalAddonsOnly
             operator: Exists
           - operator: "Exists"
             effect: "NoExecute"
           - operator: "Exists"
             effect: "NoSchedule"
         serviceAccountName: calico-node
         priorityClassName: system-cluster-critical
         containers:
         - image: calico/typha:v3.32.2
           name: calico-typha
           ports:
           - containerPort: 5473
             name: calico-typha
             protocol: TCP
           env:
             - name: USE_POD_CIDR
               value: "true"
             # Disable logging to file and syslog since those don't make sense in Kubernetes.
             - name: TYPHA_LOGFILEPATH
               value: "none"
             - name: TYPHA_LOGSEVERITYSYS
               value: "none"
             # Monitor the Kubernetes API to find the number of running instances and rebalance
             # connections.
             - name: TYPHA_CONNECTIONREBALANCINGMODE
               value: "kubernetes"
             - name: TYPHA_DATASTORETYPE
               value: "kubernetes"
             - name: TYPHA_HEALTHENABLED
               value: "true"
             # Location of the CA bundle Typha uses to authenticate calico/node; volume mount
             - name: TYPHA_CAFILE
               value: /calico-typha-ca/typhaca.crt
             # Common name on the calico/node certificate
             - name: TYPHA_CLIENTCN
               value: calico-node
             # Location of the server certificate for Typha; volume mount
             - name: TYPHA_SERVERCERTFILE
               value: /calico-typha-certs/typha.crt
             # Location of the server certificate key for Typha; volume mount
             - name: TYPHA_SERVERKEYFILE
               value: /calico-typha-certs/typha.key
           livenessProbe:
             httpGet:
               path: /liveness
               port: 9098
               host: localhost
             periodSeconds: 30
             initialDelaySeconds: 30
           readinessProbe:
             httpGet:
               path: /readiness
               port: 9098
               host: localhost
             periodSeconds: 10
           volumeMounts:
           - name: calico-typha-ca
             mountPath: "/calico-typha-ca"
             readOnly: true
           - name: calico-typha-certs
             mountPath: "/calico-typha-certs"
             readOnly: true
         volumes:
         - name: calico-typha-ca
           configMap:
             name: calico-typha-ca
         - name: calico-typha-certs
           secret:
             secretName: calico-typha-certs
   TXT
   kubectl apply -f ~/manifests/typha-deployment.yaml
   ```
8. Install its service.

   ```shell
   cat <<TXT | tee ~/manifests/typha-service.yaml
   apiVersion: v1
   kind: Service
   metadata:
     name: calico-typha
     namespace: kube-system
     labels:
       k8s-app: calico-typha
   spec:
     ports:
       - port: 5473
         protocol: TCP
         targetPort: calico-typha
         name: calico-typha
     selector:
       k8s-app: calico-typha
   TXT
   kubectl apply -f ~/manifests/typha-service.yaml
   ```
9. Test Typha out by is using TLS. This will produce an specific error, but
   that is to be expected.

   ```shell
   TYPHA_CLUSTERIP="$(kubectl get svc -n kube-system calico-typha -o jsonpath='{.spec.clusterIP}')"
   curl https://[${TYPHA_CLUSTERIP}]:5473 -v --cacert ~/certs/typhaca.crt
   ```

## Install calico/node

calico/node runs three daemons

* Felix, the Calico per-node daemon
* BIRD, will be disabled.
* confd, a daemon that watches the Calico datastore for config changes and
  updates BIRD's config files.

### Provision Certificates

1. Create the key `calico/node` will use to authenticate with Typha and the
   certificate signing request (CSR).

   ```shell
   openssl req -newkey rsa:4096 \
           -keyout ~/certs/calico-node.key \
           -nodes \
           -out ~/certs/calico-node.csr \
           -subj "/CN=calico-node"
   ```
2. Sign the Felix certificate with the CA we created earlier

   ```shell
   openssl x509 -req -in ~/certs/calico-node.csr \
      -CA ~/certs/typhaca.crt \
      -CAkey ~/certs/typhaca.key \
      -CAcreateserial \
      -out ~/certs/calico-node.crt \
      -days 365
   ```
3. Store the key and certificate in a Secret that calico/node will access.

   ```shell
   cd ~/certs
   kubectl create secret generic -n kube-system calico-node-certs \
       --from-file="${HOME}/certs/calico-node.key" \
       --from-file="${HOME}/certs/calico-node.crt"
   ```
4. Validate.

   ```shell
   curl https://calico-typha:5473 -v --cacert "${HOME}"/certs/typhaca.crt --resolve calico-typha:5473:${TYPHA_CLUSTERIP} --cert "${HOME}/certs/calico-node.crt" --key "${HOME}/certs/calico-node.key"
   ```

### Install daemon set

We'll configure IPv6 only support by adding the following variable settings to
the environment for the calico-node container:

In the `calico-node` DaemonSet manifest, ensure the container environment
variables are set as:
* IP6: autodetect
* FELIX_IPV6SUPPORT: true
* CALICO_IPV6POOL_NAT_OUTGOING: true
* CALICO_IPV6POOL_CIDR: `<same as pod cidr passed to controller-manager>`
* IP: none
* CALICO_IPV4POOL_VXLAN: Always
* CALICO_ROUTER_ID: hash
* IP6_AUTODETECTION_METHOD: cidr=2001:4860::0/64
* CALICO_NETWORKING_BACKEND: vxlan

When Calico is configured to use the Kubernetes API as the datastore, the
environments used for BGP configuration are ignored—this includes selection
of the node AS number (AS) and all of the IP selection options (IP, IP6,
IP_AUTODETECTION_METHOD, IP6_AUTODETECTION_METHOD).

Switching from IP-in-IP to VXLAN set `CALICO_IPV4POOL_VXLAN`, for details see https://docs.tigera.io/calico/latest/getting-started/kubernetes/self-managed-onprem/config-options#switching-from-ip-in-ip-to-vxlan

`CALICO_IPV6POOL_NAT_OUTGOING: true` to enable outbound NAT for Pods with
private IP addresses.

If you did not use `kubeadm` to set up the cluster then use
`CALICO_IPV6POOL_CIDR` it to the same as pod cidr passed to controller-manager.

For IPv6 only mode, set `IP6: autodetect` and `IP` to "none" to disable
autodetection of IPv4.

NOTE: By default, Felix programs cluster routes for VXLAN IP pools, while
BGP distributes cluster routes for IP-in-IP pools and for pools with no
encapsulation.

Setting CALICO_ROUTER_ID to value hash will use a hash of the configured
nodename for the router ID. This should only be used in IPv6-only systems with
no IPv4 address to use for the router ID. Since each node chooses its own router
ID in isolation, it is possible for two nodes to pick the same ID resulting in
a clash. The probability of such a clash grows with cluster size so this feature
should not be used in a large cluster (500+ nodes).

When Calico is used for routing, each node must be configured with an IPv4 address and/or an IPv6 address that will be
used to route between nodes. `calico/node` container can be configured to
autodetect these IP addresses. The IP autodetection methods are provided to improve the selection of the correct
address, by limiting the selection based on suitable criteria for your deployment.

Setting `CALICO_NETWORKING_BACKEND` to `vxlan` mode, only VXLAN networking is
provided; BIRD and BGP are disabled.

kind: DaemonSet
apiVersion: apps/v1
metadata:
  name: calico-node
  namespace: kube-system
  labels:
    k8s-app: calico-node
spec:
  selector:
    matchLabels:
      k8s-app: calico-node
  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1
  template:
    metadata:
      labels:
        k8s-app: calico-node
    spec:
      nodeSelector:
        kubernetes.io/os: linux
      hostNetwork: true
      tolerations:
        # Make sure calico-node gets scheduled on all nodes.
        - effect: NoSchedule
          operator: Exists
        # Mark the pod as a critical add-on for rescheduling.
        - key: CriticalAddonsOnly
          operator: Exists
        - effect: NoExecute
          operator: Exists
      serviceAccountName: calico-node
      # Minimize downtime during a rolling upgrade or deletion; tell Kubernetes to do a "force
      # deletion": https://kubernetes.io/docs/concepts/workloads/pods/pod/#termination-of-pods.
      terminationGracePeriodSeconds: 0
      priorityClassName: system-node-critical
      containers:
        # Runs calico-node container on each Kubernetes node.  This
        # container programs network policy and routes on each
        # host.
        - name: calico-node
          image: calico/node:v3.32.2
          env:
            - name: CALICO_NETWORKING_BACKEND
              value: vxlan
            # Use Kubernetes API as the backing datastore.
            - name: DATASTORE_TYPE
              value: "kubernetes"
            - name: FELIX_TYPHAK8SSERVICENAME
              value: calico-typha
            # Wait for the datastore.
            - name: WAIT_FOR_DATASTORE
              value: "true"
            # Set based on the k8s node name.
            - name: NODENAME
              valueFrom:
                fieldRef:
                  fieldPath: spec.nodeName
            # Cluster type to identify the deployment type
            - name: CLUSTER_TYPE
              value: "k8s,kubeadm"
            # Disable file logging so kubectl logs works.
            - name: CALICO_DISABLE_FILE_LOGGING
              value: "true"
            # Set Felix endpoint to host default action to ACCEPT.
            - name: FELIX_DEFAULTENDPOINTTOHOSTACTION
              value: "ACCEPT"
            - name: FELIX_IPV6SUPPORT
              value: "true"
            # Set Felix logging to "info"
            - name: FELIX_LOGSEVERITYSCREEN
              value: "info"
            - name: FELIX_HEALTHENABLED
              value: "true"
            # Location of the CA bundle Felix uses to authenticate Typha; volume mount
            - name: FELIX_TYPHACAFILE
              value: /calico-typha-ca/typhaca.crt
            # Common name on the Typha certificate; used to verify we are talking to an authentic typha
            - name: FELIX_TYPHACN
              value: calico-typha
            # Location of the client certificate for connecting to Typha; volume mount
            - name: FELIX_TYPHACERTFILE
              value: /calico-node-certs/calico-node.crt
            # Location of the client certificate key for connecting to Typha; volume mount
            - name: FELIX_TYPHAKEYFILE
              value: /calico-node-certs/calico-node.key
            - name: CALICO_IPV6POOL_NAT_OUTGOING
              value: "true"
            - name: CALICO_IPV6POOL_CIDR
              value: "fd12:3456:789a:1000::/56"
            # Switching from IP-in-IP to VXLAN see https://docs.tigera.io/calico/latest/getting-started/kubernetes/self-managed-onprem/config-options#switching-from-ip-in-ip-to-vxlan
            - name: CALICO_IPV4POOL_VXLAN
              value: Never
            - name: CALICO_IPV6POOL_VXLAN
              value: Always
            - name: CALICO_IPV4POOL_IPIP
              value: Never
            - name: USE_POD_CIDR
              value: "true"
            - name: CALICO_IPV6POOL_DISABLE_BGP_EXPORT
              value: "true"
          securityContext:
            privileged: true
          resources:
            requests:
              cpu: 250m
          lifecycle:
            preStop:
              exec:
                command:
                - /bin/calico-node
                - -shutdown
          livenessProbe:
            httpGet:

              port: 9099

            - mountPath: "/calico-typha-ca"
              name: calico-typha-ca
              readOnly: true
            - mountPath: /calico-node-certs
              name: calico-node-certs
              readOnly: true
      volumes:

            path: /lib/modules
        - name: var-run-calico
          hostPath:
            path: /var/run/calico
        - name: var-lib-calico
