# Add Metrics Server

Metrics Server collects resource metrics from Kubelets and exposes them in
`kube-apiserver` through the API. It provides the ability to autoscale
pipelines, for use by Horizontal Pod Autoscaler and Vertical Pod Autoscaler.
It can also be accessed by `kubectl top`, making it easier to debug autoscaling
pipelines.

NOTE: Metrics Server is meant only for autoscaling purposes.

Read more about it at [metrics-server]. Also, see [metrics-server CLI help].

## Install

Before deploying metrics server, PLEASE verify the `kubelet` on each or at least
a few nodes have correct hostname and IPs listed as "Subject Alternative Name"
in their certificates. You can check with a command like:

```shell
sudo cat /var/lib/kubelet/pki/kubelet-server-current.pem | openssl x509 -text -noout
```
Without this `metric-server` may fail to perform TLS verification and generate
the correct certificates when it starts up, and cause it to fail.

Check the option `--kubelet-preferred-address-types` - to set your preferred
priority of node address types used when determining an address for connecting
to a particular node (default [Hostname,InternalDNS,InternalIP,ExternalDNS,
ExternalIP])

1. Drop back into the `control-panel-01` terminal and apply the `metrics-server`
   manifest:
   ```shell
   wget -O metrics-server.yaml https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
   vi metrics-server.yaml
   ```

   Edit the Deployment section to add the following arguments:
   ```yaml
   containers:
      - args:
        # - ...
        - --kubelet-certificate-authority=/etc/kubernetes/pki/ca.crt
        - --requestheader-client-ca-file=/etc/kubernetes/pki/front-proxy-ca.crt
        - --tls-cert-file=/etc/kubernetes/pki/front-proxy-client-metrics-server.crt
        - --tls-private-key-file=/etc/kubernetes/pki/front-proxy-client-metrics-server.key
        - --kubelet-client-certificate=/tmp/kubelet/tls/metrics-server-kubelet.crt
        - --kubelet-client-key=/tmp/kubelet/tls/metrics-server-kubelet.key
   ```

   NOTE: The options `--requestheader-client-ca-file`, `--tls-cert-file`, and
   `--tls-private-key-file` file are for connecting to the `kube-apiserver` API.
   While `--kubelet-client-certificate`, `--kubelet-client-key`, and
   `--kubelet-certificate-authority` This certificate is used for mutual TLS
   authentication, allowing the kubelet to verify that `metrics-server` is an
   authorized client.

   ```shell
   kubectl apply -f metrics-server.yaml
   ```

NOTE: You can easily add a sidecar for looking around the Pod:

```yaml
kubectl debug -it --image=busybox --target=metrics-server -n kube-system
```

NOTE: To see all options for the metrics server, you can run

```shell
docker run --rm k8s.gcr.io/metrics-server/metrics-server:v0.8.1 --help
```

## Generate Front-Proxy Client Certificate

**This section is optional**.

With the `--requestheader-client-ca-file` option you can specify a root
certificate bundle for verifying client certificates on incoming requests.

This certificate will be used in the [Authentication Flow] for Extended API's.

1. Make a workspace on the `control-plane-01`:

   ```shell
   mkdir -p ~/certs && cd ~/certs
   ```
2. Make an OpenSSL config to aid in generating a key/cert pair:

   ```shell
   cat /vagrant/openssl-metrics-server.conf.tmpl | envsub | tee ~/certs/openssl-metrics-server.conf
   ```
3. Make a front proxy client cert for the `metrics-server`:

   ```shell
   CERT_BITS=2048
   CERT_DAYS=365
   cert_dir=/etc/kubernetes/pki
   CERT_CONF="openssl-metrics-server.conf"
   CERT_NAME="front-proxy-client-metrics-server"
   # Make key
   openssl genrsa -out "${CERT_NAME}.key" ${CERT_BITS}
   # Make a csr.
   openssl req -new -key "${CERT_NAME}.key" -sha256 \
       -config "${CERT_CONF}" -section "front_proxy_client" \
       -out "${CERT_NAME}.csr"
   # Make a certificate.
   sudo openssl x509 -req -days ${CERT_DAYS} -in "${CERT_NAME}.csr" \
       -copy_extensions copyall \
       -CAkey "${cert_dir}/front-proxy-ca.key" \
       -sha256 -CA "${cert_dir}/front-proxy-ca.crt" \
       -CAcreateserial \
       -out "${CERT_NAME}.crt"
   ```
4. Save certs as secrets in the cluster to map as a volume for the Pod running
   on any worker node:

   ```shell
   kubectl -n kube-system create secret generic \
       metrics-server-tls \
       --from-file=./${CERT_NAME}.crt \
       --from-file=./${CERT_NAME}.key
   ```
5. Modify the `/etc/kubernetes/manifest/kube-apiserver.yaml` and add options
   `--enable-aggregator-routing=true` and
   `--requestheader-allowed-names=front-proxy-client,metrics-server`.

   NOTE: Once you edit the `kube-apiserver.yaml` file, it and other components
   will restart. This should take about a minute. Watch it closely.

## Generate kubelet Client Certificate

Generate a certificate for the metrics server to authenticate with each
`kubelet` in the cluster.

1. Gather all hostnames and IPs (v4 and v6) addresses from all nodes and set them
   in an environment variable `ALL_KUBELET_SANS`
   ```text
   export ALL_KUBELET_SANS="DNS:control-plane-01, DNS:worker-01 ,DNS:worker-02 , IP:127.0.0.1, IP:192.168.56.11, IP:2000:192:168:56::11, IP:192.168.56.21, IP:2000:192:168:56::21, IP:192.168.56.22, IP:2000:192:168:56::22"
   ```
2. Generate a key and certificate (signed by the Kubernetes CA) for each node's
   `kubelet` to use.
   ```shell
   cd ~/certs
   CERT_BITS=2048
   CERT_DAYS=365
   cert_dir=/etc/kubernetes/pki
   KUBELET_CONF="openssl-metrics-server.conf"
   KEY_PAIR="metrics-server-kubelet"

   # generate a new kubelet OpenSSL configuration.
   cat /vagrant/${KUBELET_CONF}.tmpl | envsubst | tee ${KUBELET_CONF}

   # generate a key
   openssl genrsa -out "${KEY_PAIR}.key" ${CERT_BITS}

   # make a CSR
   openssl req -new -key "${KEY_PAIR}.key" -sha256 \
       -config "${KUBELET_CONF}" -section "metrics_server" \
       -out "${KEY_PAIR}.csr"

   # Use the cluster CA to sign the CSR and make a certificate that can connect to the kubelet.
   sudo openssl x509 -req -days ${CERT_DAYS} -in "${KEY_PAIR}.csr" \
       -copy_extensions copyall \
       -CAkey "${cert_dir}/ca.key" \
       -sha256 -CA "${cert_dir}/ca.crt" \
       -CAcreateserial \
       -out "${KEY_PAIR}.crt"
   ```
3. Test:
   ```shell
   sudo curl -v --cacert /etc/kubernetes/pki/ca.crt \
     --cert "${HOME}"/certs/metrics-server-kubelet.crt \
     --key "${HOME}"/certs/metrics-server-kubelet.key \
     https://control-plane-01:10250/metrics
   ```
4. Now lets embed these on a secret:

   ```shell
   kubectl -n kube-system create secret generic \
       metrics-server-tls \
       --from-file=${HOME}/certs/metrics-server-kubelet.crt \
       --from-file=${HOME}/certs/metrics-server-kubelet.key
   ```

   NOTE: If you make a front-proxy client certificate, be careful not to
   overwrite it here.
